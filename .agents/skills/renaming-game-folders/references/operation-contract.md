## 分批与搜索

- 用户人工补充模式必须在每批使用绑定当前 analysis 的独立 `user-supplements.json`。
  本地编译和搜索均显式传入同一文件；搜索把其中详情链接并入候选种子，三来源预检、真实
  回源、逐字段采用和批内阶段顺序保持不变。人工确认非游戏的未决 EXE 保留在扫描事实中，
  但不进入正式预览条目或游戏统计。人工补充正文和摘要进入搜索事实与审批材料，任一修改
  都使旧批准失效。

- 全局层级确定后，按原始完整路径处理；每批最多 10 个根游戏。单游戏计一个，系列及
  全部成员合计计一个且不得拆批。批内游戏与来源可有界并发，输出仍按原路径排序。
- 每批严格分三阶段：先完成该批全部叶子的本地 Skill 判断和整批校验，再完成该批全部
  叶子的三来源搜索，最后完成该批全部叶子的远程 Skill 判断和整批校验。禁止按单个
  游戏依次完成全部阶段；中断后从该批尚未完成的阶段重新开始。
- 每次执行 `search` 时，在任何游戏查询开始前，必须在相同权限环境用生产客户端对
  VNDB、DLsite、Steam 的正式首轮端点完成三来源连通预检，同时验证 HTTP、JSON 与最低
  响应结构。三个来源全部通过后才能开始整批搜索；任一来源连接、超时、HTTP、JSON 或
  响应结构失败时整批停止，不写 `search-evidence.json`，也不得把故障记为数据库无结果。
  正常返回空候选属于连通成功。若仅受限沙箱失败，正式搜索必须在获准网络环境执行。
- 游戏查询先按来源、查询方法、实际标题词、指定来源 ID、制作方及结果上限查本地
  `remote-search-cache.json`。有完整候选的成功结果从获取时起 365 天内复用；
  到期、空结果、错误或摘要损坏的缓存须重新请求来源。正式三来源预检不读取缓存。搜索证据必须记录命中
  状态与候选原始获取时间，不能把旧缓存命中称为本轮实时回源。
- 层级编译和搜索分别生成 `local-review-packet.json` 与 `remote-review-packet.json`
  供 Skill 快速阅读。包内注明完整证据文件和绑定指纹；截断或冲突时回读原始证据，
  语义编译仍只以完整阶段文件为准。
- 文件2 `search-evidence.json` 保存完整搜索事实。原名标题首轮、统一网络错误重试、
  各站短词补搜和回源详情必须保留实际关键词、状态、候选、错误及运行摘要；重试可更新
  该语言轮的最终状态，但必须另存首轮错误与实际重试次数，不得把早期故障伪装成无结果。
- 首轮 VNDB 按文件1的首选关键词请求官方 API，DLsite 标题发现只用 `suggest`；
  本地 DLsite ID 优先回源，但若全部是与当前本体标题身份不符的 DLC，仍用原名标题
  `suggest` 查本体并保留 DLC 候选；本体排在该轮展示首位。Steam 先用 Community `SearchApps`，若原名中文词
  缺少精确标题候选，再顺序使用官方 `storesearch` 简体中文入口查同一词；不得发送
  远程译名或并行请求第二条发现链路。同一来源内清理后完全相同的多语种查询只请求一次。三来源
  首轮全部结束后，只对超时、HTTP 或连接错误统一重试一次；正常无结果不重试。显式
  `retry-network-errors` 仅在正式搜索后仍有网络错误时用于人工恢复。
- 第二轮后第三阶段改为各来源独立的短词补搜：仅该来源无候选、无持续网络错误，且 Skill
  已为原名标题语言槽审定严格更短的核心词时执行。某来源已有候选不阻断其他空来源。
  每个来源按日、中、英短词顺序查询并去重，得到候选即停止该来源补搜；网络错误与正常
  无结果分别记录。正式流程不访问 Google。
- 所有首轮和短词发送前使用同一清理：只保留 Unicode 字母、
  组合标记和数字，其他字符替换为空格并压缩空白；数字、罗马数字与 `DLC` 等身份词保留。
  完整原始标题只保存为证据并用于回源同一性校验，不作为带符号查询发送。各轮成功、
  正常无结果、错配和网络错误分别记录。
- 每个来源内部按日、中、英顺序执行当前叶子原 basename 已有的首选关键词；仅用户本轮
  明确提供并通过绑定指纹的 `allow_non_basename_search` 校验的完整标题可作为当前叶子的
  例外关键词。只有当前来源
  左侧较早语言轮成功候选已经返回与当前原名查询词规范化后完全一致的语言字段时才
  标记 `covered`；包含匹配、额外版本或特典前缀不能覆盖。缺少原名关键词的
  语言标记 `missing`。来源返回的译名只作候选证据，不反向用于三来源查询。
  本体与独立 DLC 的候选身份必须一致。
- 本地 RJ/VJ/BJ/EJ 与 Steam AppID 优先于标题发现；本地 VNDB ID 只作证据。只有绑定
  本轮指纹的用户候选种子可直接读取 VNDB ID。
- 公共 HTTP 请求默认 4 秒超时、最多 2 次尝试和单游戏来源预算。Steam 跨游戏串行、
  单游戏详情最多 2 路；DLsite 单游戏详情最多 4 路。并发结果按固定游戏与来源顺序
  重组。
- 每批分别记录脚本首轮/重试/短词补搜、AI 本地/远程判断的墙钟时间、根游戏数、
  叶子数和每根平均耗时；当前未实现的阶段必须明确记为未实现，不得填入虚假时长。

## 局部更新预览

- 已有汇总预览需要更正部分游戏时，`scan-evidence --include-path` 可只枚举选定子树中的启动项，
  随后仍按层级、本地语义、搜索、远程语义和正式单批预览完整处理被选部分。选中系列时必须包含
  系列外层与全部成员；普通单游戏可单独更新。扫描根路径必须与旧汇总完全相同。
- 在同一扫描根生成当前指纹的单批正式 manifest 后，可执行
  `update-combined-preview <旧汇总 manifest> <更新 manifest...> --output-dir <新目录>`。
  它以稳定游戏/系列 ID 替换旧行，保留其他行的语义和搜索结果，复验保留目录指纹、整份汇总动作、
  目标冲突和快捷方式，再生成新的汇总 manifest、HTML、含项目文件动作的目录预览和批准码。
- 局部更新只接受旧汇总中已存在的条目；新出现/删除的游戏、改变的层级，或只更新系列一部分时，
  整批拒绝并要求完整重建。旧批准码立即失效，新预览仍须用户单独批准。
- 为保证批准安全，局部更新仍读取整个根目录的路径、大小和修改时间以计算全根指纹，并校验所有
  未选中动作来源目录；它省去未选子树的 EXE/SWF 发现、语义判断和在线搜索，不代表跳过最终整批预检。

## 语义产物边界

本地字段、目标命名、系列传播、英文路径保护、远程字段闭包与本地尽力命名的判断规则只在
[语义契约](semantic-contract.md)维护。运行层只消费已经通过编译和校验的
`local-semantics.json`、`search-evidence.json` 与 `remote-semantics.json`，不得重新解析
`analysis-input.local_fields`、候选详情或目录名称来补字段。

## 动作、审计与派生产物

- 每个可信且唯一的详情 URL 都规划为游戏目录内 `.url`；文件名在来源 ID 前加入可证实的年份和年龄状态，
  例如 `[VNDB] 2006_18+_v487.url`，明确低于 18 的年龄状态写 `全年龄`；资料缺失时省略对应部分，
  不猜测或使用未知占位。VNDB 年份取所有关联 Release 中最早的已知年份，
  年龄取全部 Release 的最高 `minage`；Release 查询必须分页到最后一页。DLsite 年份采用其作品
  登记日期，Steam 年份采用 Steam 商店发行日期，均不得冒充作品在其他平台的全球首次发行年份。
  已确认最高年龄低于 18 时，目标名称同时加 `#来源全年龄`，来源为已采用候选的
  `audience_source.source`；没有年龄资料时不得臆断全年龄。
  多个最终采用来源合并时，目标年龄按有证据来源中的最高限制汇总：任一成人来源即为成人，不能添加
  `#来源全年龄`；只有已知年龄来源全部为全年龄时才添加，并按既定来源优先级取唯一证据来源。
  若输出合并年份，取已知来源中的最早年份；
  快捷方式仍分别标记其自身来源的年份和年龄，不将某来源日期冒充另一来源日期。
  即使跳过重命名，快捷方式动作也必须进入 manifest、预览和批准哈希。系列外层不联网、不建快捷方式。
- 新批次不寻找直属 CG/存档资料目录，不规划 `@CG` / `@存档` 改名；
  旧回执若含已执行的附属目录动作，撤销仍按原清单验证和逆向处理。
- 每次完整搜索创建唯一日期时间日志目录，保存完整搜索证据及每游戏一个目录
  SHA-256。最终预览复验后，在同一目录补齐 manifest、重命名、快捷方式和批准材料。
- 每次正式单批、跨批汇总或撤销预览都成对生成 `preview.html` 与
  `folder-structure-preview/`。目录预览模拟批准清单中的目标目录层级，并显示批准动作会新增或恢复的
  文件：`.url` 使用清单 URL 内容，英文路径保护 `.txt` 保持零字节；不复制游戏文件或其他原有文件。
  同目录生成 `folder-structure-preview.json`，记录目录数、项目文件数、相对路径和类型。
- 预览必须位于扫描根外，不得改名、移动或写入原游戏目录。跨批汇总在写出这对产物前
  必须完成只读整批预检；扫描根、来源或目标发生漂移时停止，不得继续发布旧 manifest
  的正式预览。正式语义预览同时原子更新 `data/successful-games.csv`。CSV 只收录查询成功
  且可执行的叶子，按来源 ID 去重并稳定排序；非空冲突保留旧值，明细写入 `decisions.md`
  与日志。
- 目录预览优先同卷原子改名；Windows 因后代路径拒绝访问时，可用目标外
  `.incomplete` 标记保护后直接创建目录与批准文件。成功后删除标记，失败产物不得进入批准结果。

## 预览

正式预览的数据来源固定如下，任何阶段都不得越权：

- 原文件夹名称从真实 `manifest.source` basename 读取；文件1只提供无损分槽位置。
- “来源搜索结果”和日中英三轮从最终文件2读取。
- 预计名称由文件1的本地字段与文件3的远程字段经脚本格式化为真实
  `manifest.target` basename；不得由文件3直接写名称。
- 加粗、标红、标蓝、来源贡献与状态底色由脚本比较真实 source/target 并结合三阶段审计
  字段计算。AI 不得直接编辑 HTML 来改变结果。
- apply/undo 只消费批准哈希绑定的 manifest、快照和回执，绝不消费 HTML。

### 名称列与差异

- 正式表固定七列。两个名称格先固定为空白占位、制作方、日文、中文、英文、合集范围、
  引擎、版本/DLC 八个槽位，再为每个末尾标签各增加一个独立槽位；非合集的范围槽留空，
  左右两侧按语言和
  标签语义对齐，没有对应字段时保留空行，不得用后续字段补位。原列从
  `Path(source).name`、目标列从可执行 manifest 的 `Path(target).name` 取得真实
  basename，再按 developer、实际日中英标题、合集范围、引擎、版本/DLC 和逐个标签的真实字面片段
  切成多行；不同语言即使在原 basename 中顺序不同，也按日、中、英槽位显示并以
  `data-basename` 保留逐字符真实原名。换行和语义排序只用于预览，不改变 manifest 或
  apply 名称。跳过项及未解析工具没有可执行 `target`，其目标列和 `data-basename` 必须
  显示 `Path(source).name`，并逐行复用原列已经验证的语义槽，明确表示保持原名；左右
  每一行必须完全相同，不得留空、重新分槽或据语义字段拼出部分预计名。
  目标末尾元数据组在真实 basename 中仍只有一对方括号。
- `original_preview_lines` 与 `target_preview_lines` 只可定位 basename 中真实存在的切点
  并提供差异着色，不得用于拼装、摘要、翻译、增删或重排显示名称。系列继承、说明文本
  字段、`#uncheck/#eng` 或远程字段均不得进入原列；目标各显示行连接后若与 manifest
  `target` basename 不一致必须拒绝生成正式预览。
- `propagated_title_context` 仅记录接收方日中英标题槽全空时填入的共同标题。不得改变原文件夹列或远程来源事实；预计标题传播行须标蓝。
- 可执行项按同一对齐语义槽使用同一字符差异操作流：`delete` 与 `replace` 覆盖的每个
  原字符必须标红，`insert` 与 `replace` 覆盖的每个目标字符必须加粗，相同子序列保持
  普通字重。不得以“轻微修改”、繁简转换、大小写、空格、标点或版本格式化为由隐藏
  原字符的删除/替换；任一应标红字符未被覆盖都必须拒绝正式预览。语言标题仅新增前导
  `=` 且正文与原字段一致时只加粗 `=`，
  并且不计为来源贡献；标签或标题传播导致的修改同时标蓝。
  合集从成员共同语义取得且合集表面原名中不存在的制作方/共同标题必须记录传播索引并标蓝；成员填入的共同标题同样标记传播。
  目标的 `合集` 或 `合集1~2` 片段移到全部语言行之后的独立显示行，
  原名显式范围也在该行对齐，不归入任一语言行。
  跳过项的两侧名称必须逐行相同且不得把保留原文标为删除或新增。名称列及搜索字段中的红色文字
  只表示被删除的原文片段；加粗只表示新增或替换。developer 冲突只记录审计，不额外着色；
  错配/网络错误时仅来源结果和三种语言搜索轮状态格使用浅琥珀色；预计名称格不铺琥珀底。
  无结果必须列出实际尝试的来源首轮、网络重试与各站短词补搜（如发生）。原 developer
  为空时，远程值只按新增字段加粗。
- 合集条目在第一名称大格显示自身原名与预计名。子游戏条目保留两个名称大格：第一格
  显示子游戏自身原名与预计名，第二格以灰底显示所属合集原名与预计名。英文路径保护生成的规范名称 TXT 使用
  英文投影前本来要采用的完整规范 basename 加 `.txt`，在第一名称大格下新增独立大行，只占预计
  重命名名称列，并按 developer、日中英标题和末尾元数据分行；系列成员中必须位于子游戏名称行
  之后、灰色所属合集名称行之前。序号单元格必须把该新增行计入 `rowspan`，TXT 行不得再创建
  序号单元格，确保视觉上仍处于预计重命名名称列；其余五个可见列为空。原列结构化标题全空时，完整
  basename 原样放入一个字段。

### 搜索轮与来源

- 每来源的日、中、英轮各固定 10 行：`搜索：关键词`、制作方、返回日/中/英、年份、年龄、
  保留一行空白、`来源搜索 成功/无结果/网络错误`、`短词补搜：关键词 成功/无结果/网络错误`。
  未执行的短词行留空；年份与年龄只来自该轮实际返回页面，且必须与同一候选 `.url` 文件名的年份、年龄令牌完全一致；缺失时显示“无”，不得从本地
  内容、关联作品页或其他轮/来源补齐。VNDB Release 轮的标题与制作方只读该 Release；年份和年龄使用该 VN 全 Release 汇总值，与该 Release 快捷方式的文件名一致。三轮查询列不得显示来源 ID 或其链接。VNDB 用户种子含唯一 Release
  时，搜索必须回读该 Release 的 `languages` 与 `producers` 字段并将其作为独立 `release_pages[]`
  保存；语言轮展示 Release 页面回源字段，且语言覆盖只依据该 Release，不得用关联 v 作品页字段
  补齐。多个 Release 页不合并标题或制作方。VNDB 候选 `vNNN` 与 `rNNN` 的类型只用于内部字段隔离，
  不在三轮查询列显示页类型或 ID。标题字段逐字来自实际展示的
  页面，不得把作品页标题标称为 Release 页字段。缺失或已覆盖只显示“跳过”；
  来源状态行显示独立的原词搜索状态，短词状态行只在真实执行短词查询时显示；网络异常显示具体错误。搜索关键词不得进入返回字段或
  目标名。
- 每站所有候选分别审核；同站多个候选由 Skill 在 `preview_candidate_keys` 指定唯一最佳
  展示 key。三个语言轮合计只展示该候选一次；其他成功轮保留实际查询和成功状态，
  不显示其他候选的详情。单候选站自动展示该候选。
- “来源搜索结果”列只描述同一来源右侧展示的唯一最佳候选。已采用来源显示最终
  `[采用]` / `[合并采用]` 标识和可见采用候选的快捷方式编号，前三行依次为标识、
  来源名、链接；即使该来源还有被拒候选，也不得在采用格混写“未采用”理由。
  未采用来源只对右侧可见候选按 Skill 判断在第四行说明“未采用”或“仅参考”理由，
  同一理由去重并隐藏未采用编号与 URL；未展示候选的理由及参考链接不进入来源格，
  但保留在审计证据和独立快捷方式清单。最高版本与最佳标签的独立参考链接只有对应
  候选在右侧可见时才保留在第七行。不得复制三轮已显示的制作方、标题或查询状态。
- 某来源返回了候选，但该来源全部候选经 Skill 判断为非同一游戏、`source_disposition`
  为 `rejected`，且没有可信 `reference_candidates` 时，该来源格使用琥珀色警示底色；正常无结果
  为灰色，网络错误与错配使用相同琥珀色，adopted 为绿色，可信 reference 不得误标为错配。
- `field_sources` 中任一实际供给最终 developer 或日中英标题的来源都必须属于 adopted
  候选；已确认同一精确游戏并用于名称同一性佐证或补充缺失语种的来源也属于 adopted。
  只有一个 adopted 来源时标 `[采用]`，多个时全部标 `[合并采用]`。低优先级采用候选可
  返回重复名称字段，但不得覆盖 `field_sources` 已按优先级选定的唯一最终值。
- ①日文轮、②中文轮、③英文轮只把实际为最终名称新增或修改的 developer、日文、中文、
  英文返回字段加粗；脚本比较当前条目真实原 basename 的独立语义槽与最终语义字段，
  不使用已经混入合集借用或父子传播的本地对象，并对两边应用同一目标规范化。独立 DLC
  可对 `standalone_dlc_title_language` 指定的已采用远程标题追加本地身份后缀后比较，
  但轮次仍显示来源返回原文。分隔符、方括号、前导 `=` 与元数据移位等确定性格式变化
  不得算作来源贡献；最终采用组的每个来源只要实际返回与最终值相同的字段，且该字段相对
  原名发生语义变化，就在其语言轮加粗，即使唯一 `field_sources` 由更高优先级来源占据。
  同来源返回多个候选时，当前语言轮展示的候选必须属于最终采用组；不能仅凭来源被采用或
  字段值碰巧相同就加粗未采用候选。
  同站其他已采用候选的字段仍参与最终名称和审计，但不在三轮预览显示或加粗。
  固定前缀 `制作方：`、`日：`、`中：`、`英：` 保持常规字重，只加粗返回值。
  同来源未采用字段及只搜索成功的字段保持常规字重。预计名称列另按
  真实原/目标 basename 的字面差异显示；二者完全相同时任何字段都不得加粗。
  某轮展示的候选字段还必须在规范化后等于最终采用值才可加粗；同来源第一候选不是
  最终采用值时保持普通字重。
- 返回标题中的语言版本说明保留在搜索证据并在预览标红，但进入目标标题前删除。

### 表格结构与汇总

- HTML 浅色、自适应、无水平滚动、固定表头；三个来源各占真实表格行，同一文字行
  同步高度，大格边界严格对齐。子游戏条目的第二合集格为灰底；采用来源和成功轮为
  绿色；错配/网络错误仅在来源结果及三种语言轮状态格使用浅琥珀色。预计名称格不铺该底色；正常无结果使用中性底色。
- 序号列占 4% 且保持最窄；原文件夹名称、预计重命名名称、“来源搜索结果”、
  ①日文轮、②中文轮、③英文轮六列各占 16%。七列总宽度固定为 100%。
- 跨批次统一交付 HTML 时，所有条目按完整原始路径合并成一张正式七列表并连续使用
  层级编号，不得以批次分段或生成多个主表。页面只显示一个汇总批准码；组合 manifest
  必须按展示顺序完整内嵌各批 manifest、逐项复验各批内部哈希，并把全部动作合并后在
  首个变更前统一预检。任一子清单、顺序、根或指纹变化都必须使汇总码失效。
- 正式与阶段 HTML 页首必须显示 manifest 的扫描根，并只向用户显示独立游戏数、合集数和
  合集内子游戏数。叶子游戏与主条目总数只用于内部一致性校验，不显示给用户。合集父项只
  计合集，不重复计为游戏；统计前按规范化原始路径拒绝重复，并确认每个合集子游戏的父项
  存在，不得按批次数或样例推断。
  每个 schema v2 单批 manifest 与汇总 manifest 都必须把预览契约版本纳入批准哈希，
  组合前和 apply 前必须复验当前版本；渲染契约变化后全部旧批准码必须失效。
- 单一可信来源标 `[采用]`；属于同一精确游戏的多个采用来源即使制作方不同也均标
  `[合并采用]`。本地制作方不参与来源采用筛选或最终远程 developer 选值。
- 来源快捷方式按游戏目录合并为一行。条目按原始完整路径排序；系列为主序号，成员
  使用层级序号。
- 经层级审核、比单游戏多一层的多游戏组织父目录先用独立批准清单整体迁入扫描根
  `~合集/` 并重新扫描；语义系列已嵌在该父层内时保留嵌套层级，仅无此父层的系列直入
  `~合集/`。共同语义不足以规范化 basename 时保留原名；子游戏按父移动后的
  `runtime_source` 继续规划，独立游戏的查询失败路径不变。

### 阶段进度页

- 处理中如维护唯一 `preview.html`，须复用正式渲染器并显示当前阶段、该阶段完成数与
  批次总数，但不包含 manifest 或批准哈希且不可批准。三个阶段全部完成后的正式预览
  覆盖同一路径，不保留第二个 HTML。

## 批准、apply 与 undo

- 新的移动、建目录、空 TXT 和 `.url` 创建必须先进入 JSON manifest、
  Markdown/HTML 预览并由批准哈希覆盖；apply 前完成整批预检。
- 一份完整预览只接受一次针对其哈希的明确批准。扫描根、include-path、目录内容、
  搜索运行 ID、语义、manifest、名称、动作或快捷方式任一变化，旧批准立即失效。
  用户单独回复 `v` 只批准当时明确交付的那份正式预览。
- 跨批组合 manifest 使用一个外层 SHA-256 批准码；外层同时绑定有序子 manifest、各自
  内部批准哈希和扁平动作视图。`apply` 必须先复验外层和全部子哈希，再以组合清单执行
  一次快照、整批预检、事务式动作及失败回滚。
- apply 前再次复验扫描根指纹、manifest 和批准哈希；任一变化在首个动作前整批停止。
- 修改游戏目录前，在扫描根外原子保存结构 JSON、Markdown 和批准清单；回执记录
  SHA-256。undo 先校验快照和已批准 manifest，再严格逆序执行。用户新增或修改内容
  只携带并报告，不得删除。

## 停止条件

语义文件过期或不合契约、低置信度语言划分、同一最高优先级来源的远程 developer 冲突或候选同一性无唯一
解释、层级候选漏/重覆盖、叶子根嵌套、目标已存在、路径越界、指纹漂移或执行预检
失败时保持跳过，并写入集中判断清单。完全无可信候选不单独导致跳过；本地语义可靠
时按本地字段尽力命名并进入 `~查询失败/`。不得猜测远程字段后继续。
